# React request repair — synthetic service evidence

A real React 18 component reproduction and replacement for a stale asynchronous
result defect. This is Douglas's own fictional sample, not a client repair or a
claim to have reproduced any advertised job. No customer files or services are
accessed. React 18.3.1 matches the React 18 briefs being researched; it is not a
claim that this is the latest React release.

Use Node 22.22.2+, 24.15.0+ or 26+ (matching jsdom's supported major versions):

```sh
npm ci --ignore-scripts
node --test tests/*.test.js
node proof.js > proof.json
```

Dependency installation requires npm registry access. The lockfile pins React,
React DOM and jsdom; dependencies are not bundled. If your normal npm cache is
unwritable, supply `--cache PATH_TO_YOUR_OWN_WRITABLE_CACHE` to npm. No host
permissions or browser profiles need to change. `proof.js` exit 0 means the
original fails at least one agreed synthetic case and the repair passes every
case; exit 2 means that comparison failed, exit 1 means execution/usage failure.

`BeforePanel.js` allows an earlier result or rejection to overwrite the latest
request state. Its missing effect cleanup also leaves requests active after
query changes and unmounts. `ResultPanel.js` closes each effect's result handler
and aborts its controller during cleanup. A loader that ignores abort still
cannot publish its late result. Deferring the loader to a microtask also avoids
starting the discarded development Strict Mode setup and captures synchronous
loader errors. The same effect dependencies include both query and loader.

The actual React DOM scenarios cover late success, late rejection, a current
pending request, query-change and unmount abort, development Strict Mode, loader
replacement, current success/error, synchronous throws and inert result text.
Seven original cases fail; all eleven repaired cases pass. The Node integration
test validates all eleven expected/actual records against the same scenarios
for both versions. Results are generated by executing the real components with
controlled promises, rather than describing simulated reducer behavior.

The loader contract is `load(query, {signal})`, returning a promise for display
text (or throwing/rejecting an error). Keep the loader identity stable across
ordinary renders, for example using an existing stable client or a suitable
`useCallback`. A changing identity restarts the effect by design. In a real fetch
integration, forward `signal` and check response status before returning text.
Abort signals request cancellation; a loader must implement it to stop transport
work. The sample does not issue fetch calls or demonstrate a backend cancellation.

This test uses jsdom's DOM model, with no native browser, network, screenshots,
layout or mobile Safari acceptance. The component exposes result text through an
output element; it is not a complete search app or accessibility audit. Adapt and
verify an authorized client's component, transport, caller behavior and acceptance
criteria separately before delivery. React discards state updates after unmount
in the original too; the unmount case establishes the abort signal only.

Official references: [effect cleanup and race conditions](https://react.dev/reference/react/useEffect)
and [flushing component updates with act](https://react.dev/reference/react/act).
The demonstration follows these concepts; it does not imply React endorsement.

Generate public-safe marketing evidence with `node build-proof.js NEW_DIRECTORY`.
Only the generated directory belongs in the software example hub at
`software/react-request/`; its return link assumes that location. This executes
the actual shared scenarios, renders expected and observed values as escaped
text, and copies the MIT runnable source plus SHA256 file manifest. Existing
output directories refuse. An interrupted build can leave incomplete output.
The manifest is consistency evidence, not authenticated provenance. Generated
source excludes node_modules; normal locked dependency installation is required.
Marketing regression fixtures are retained in ignored .marketing-test-* folders.
